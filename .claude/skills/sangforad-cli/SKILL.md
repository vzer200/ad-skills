# sangforad-cli

## Core Rules

- Work from this project-local skill source: `skills/sangforad-cli/`.
- Trigger this skill whenever the user asks for AD configuration as
  command-line text or a script, even if they do not say `sangforad-cli`.
  Examples: "生成命令行脚本", "给我离线命令", "导出可粘贴的 CLI 命令",
  "不要下发，产出配置脚本", "生成 apply.sfcli".
- Generate CLI commands only with `scripts/render_cli.py`; do not handwrite
  Sangfor AD command blocks from memory.
- Treat `adops-plan.json` or a filled `adops-bundle.yml` as the source of
  truth. If the user only provides a natural-language intent, use
  `ad-config-ops` first to generate and validate the bundle, then return here.
- Default mode is offline generation. Do not SSH, telnet, log in to a device,
  paste commands, or claim commands were executed.
- The user-facing deliverable is `apply.sfcli`. Internal plan/bundle files are
  opaque unless the user is debugging the generator.
- Tell the user to review the commands before pasting them into an AD CLI
  session. Do not present the generated commands as already applied.

## Workflow

Use the host-provided Python interpreter. In WorkBot/Linux examples this is
usually `python3`; in this Windows repository use the bundled Python path from
`CLAUDE.md` if `python3` or `python` resolves to the Windows Store placeholder.

### 1. Choose The Input

If a validated plan already exists:

```bash
python3 skills/sangforad-cli/scripts/render_cli.py --plan "$AD_OPS_WORKDIR/adops-plan.json" --workdir "$AD_OPS_WORKDIR"
```

Use `--plan` only for a real AD-OPS plan generated by `ad-config-ops`; it must
contain API `path` or `resource_path` fields. Do not rename a user-uploaded YAML
bundle to `adops-plan.json`.

If the user has filled the AD-OPS bundle YAML but no plan exists yet:

```bash
python3 skills/sangforad-cli/scripts/render_cli.py --bundle "$AD_OPS_WORKDIR/adops-bundle.yml" --ad-config-ops-root skills/ad-config-ops --workdir "$AD_OPS_WORKDIR"
```

When running from the repository checkout instead of the packaged WorkBot
layout, use `.claude/skills/ad-config-ops` as `--ad-config-ops-root`.

### 2. Use Script Summaries

`render_cli.py` prints a short JSON summary with:

- `ok`
- `operation_count`
- `cli_script`
- `artifacts`
- `workflow_contract`

Use that summary for paths and status. Do not parse or summarize generated
artifact files unless debugging `sangforad-cli` itself.

### 3. Finish

In the final response, list `apply.sfcli` as the reusable deliverable and state
that it is a pasteable Sangfor AD CLI command script. Mention that it was
generated offline and must be reviewed before pasting into a device session.

## Command Shape

Detailed rendering notes live in `references/cli-rendering.md`. Read that file
when extending the renderer or checking command syntax.

The current renderer follows the legacy AD CLI manual shape:

- `create`, `modify`, and `delete` from the AD-OPS operation action.
- URI path after `/api/ad/v3/` becomes command words, for example
  `/slb/virtual-service/{name}` becomes `slb virtual-service <name>`.
- Top-level `name` is positional and is not repeated as an option.
- Scalar payload values become `field value`.
- Objects become `field { child value ... }`.
- Arrays of scalars become `field [ item1 item2 ]`.
- Arrays of objects become `field add [ { key value ... } ]`.

## Boundaries

- This skill does not replace `ad-config-ops` template generation, schema
  validation, dependency sorting, API apply, or rollback.
- This skill does not read the PDF manual at runtime.
- If `render_cli.py` fails, stop and report the short error. Do not patch the
  CLI output by hand.
