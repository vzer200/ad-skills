# WorkBot AD 固定提示词使用说明

本文档记录当前已经纳入自动化验收的 AD 运维固定提示词、交互方式和预期结果。人工使用时尽量照抄这些短提示词，不要在提示词里塞复杂流程描述。

## 通用要求

- 每次正式验收使用新的数字员工，并上传最新 `dist/ad-skills-workbot.zip`。
- 数字员工初始化后先安装 AD skills：`请安装我刚上传的 AD skills 包，并确认 6 个 skill 都可用。`
- 所有需求都必须出现真实工具调用。若没有工具调用，应追问：`你刚才没有调用工具，请说明原因，并重新按技能要求实际调用工具。`
- WorkBot 输出时不要切换页面；若页面空白，等待输出结束后刷新查看完整内容。
- WorkBot 工具调用里 AD1/AD2 必须使用内网地址 `192.168.8.30/192.168.8.31`，不能出现外网网关地址。
- 用户正文里不要展示工具调用、命令、退出码、stdout/stderr。

## R1 巡检

### 单设备巡检

| 场景 | 固定交互 | 预期结果 |
| --- | --- | --- |
| 标准巡检 | `请对 AD1 做一次巡检。` -> `标准巡检` -> `强制` | 输出 `巡检结论 / 分类统计 / 设备基本信息 / 检查项明细 / 优化建议 / 健康评分`，检查项状态只用正常/异常并带图标。 |
| 全量巡检 | `请对 AD1 做一次巡检。` -> `全量巡检` -> `强制` | 同上，场景显示全量巡检。 |
| 安全巡检 | `请对 AD1 做一次巡检。` -> `安全巡检` -> `强制` | 同上，重点展示安全类风险和建议。 |

### 多设备巡检

| 场景 | 固定交互 | 预期结果 |
| --- | --- | --- |
| 标准巡检 | `请对 AD 所有设备做一次巡检。` -> `标准巡检` -> `强制` | 输出 `巡检结论 / 设备概览 / 全局共性问题`。 |
| 全量巡检 | `请对 AD 所有设备做一次巡检。` -> `全量巡检` -> `强制` | 同上，避免逐设备长篇明细。 |
| 安全巡检 | `请对 AD 所有设备做一次巡检。` -> `安全巡检` -> `强制` | 同上，重点列全局共性安全问题。 |

R1 验收重点：必须先查历史或连接状态再询问是否强制；实际巡检使用进度轮询，不能一次长命令跑到 WorkBot 60 秒超时；多设备模板不能出现 `巡检过程`、`原始报告`、英文检查项名或脚本名。

## R2 查询

R2 默认规则：提示词带“配置”只输出配置；带“状态/硬件/资源”才输出状态信息；默认模糊查询按配置处理。

| 场景 | 固定提示词 | 预期结果 |
| --- | --- | --- |
| 综合查询 | `帮我查一下 AD1 的配置、流量、设备状态和 SSL 证书到期时间。` | 输出配置、流量、设备状态、证书到期信息。 |
| 单设备配置 | `帮我查一下 AD1 的配置。` | 只输出配置类信息。 |
| 多设备配置 | `帮我查一下所有 AD 设备的配置。` | 查询所有 AD 设备配置，不混入状态指标。 |
| 单设备虚拟服务 | `帮我查一下 AD1 的虚拟服务配置。` | 只输出 VS 配置，不输出连接数/吞吐量等状态信息。 |
| 多设备虚拟服务 | `帮我查一下所有 AD 设备的虚拟服务配置。` | 查询所有 AD 设备 VS 配置。 |
| 单设备节点 | `帮我查一下 AD1 的节点配置。` | 输出节点/节点池相关配置。 |
| 单设备节点池 | `帮我查一下 AD1 的节点池配置。` | 输出节点池相关配置。 |
| 多设备节点池 | `帮我查一下所有 AD 设备的节点池配置。` | 查询所有 AD 设备节点池配置。 |
| 单设备证书 | `帮我查一下 AD1 的 SSL 证书到期时间。` | 输出证书名称、到期时间和风险提示。 |
| 多设备证书 | `帮我查一下所有 AD 设备的 SSL 证书到期时间。` | 查询所有 AD 设备证书到期信息。 |
| 单设备流量 | `帮我查一下 AD1 的流量情况。` | 输出流量/连接相关状态。 |
| 多设备流量 | `帮我查一下所有 AD 设备的流量情况。` | 查询所有 AD 设备流量。 |
| 单设备状态 | `帮我查一下 AD1 的设备状态。` | 输出设备状态和资源使用信息。 |
| 多设备状态 | `帮我查一下所有 AD 设备的设备状态。` | 查询所有 AD 设备状态。 |
| 单设备硬件 | `帮我查一下 AD1 的硬件状态。` | 输出硬件/资源状态。 |
| 多设备硬件 | `帮我查一下所有 AD 设备的硬件状态。` | 查询所有 AD 设备硬件状态。 |

R2 输出模板固定为 `查询结论 / 查询范围 / 查询结果`。目标行使用 `目标设备：AD1（192.168.8.30）`，不要显示 URL scheme，不要出现 `覆盖说明`，不要在 R4 回滚后追加“之前下发的资源已不在列表中”等流程上下文。

## R3 感知分析

R3 主线只保留两类稳定场景：日志分析和指定 VS 流量趋势分析。设备状态查询属于 R2。

| 场景 | 固定提示词 | 预期结果 |
| --- | --- | --- |
| VS 流量趋势 | `对 AD2 设备的 test 虚拟服务进行流量趋势分析。` | 必须先采集或读取数据库数据，再输出趋势分析；只给出比例和证据，不使用“轻微下降”等误导性风险列。 |
| 24 小时日志 | `对 AD1 设备的日志进行分析。` | 默认分析近 24 小时 ALERT/ERROR 日志，最多展示最新 20 条。 |
| 5 天日志 | `对 AD1 设备近 5 天的日志进行分析。` | 按提示词时间范围传入 `--days 5`，最多展示最新 20 条 ALERT/ERROR。 |

R3 输出模板固定为 `感知结论 / 分析结果 / 结论边界`。日志必须包含告警和错误级别；时间范围过大时按时间倒序截取最近 20 条。

## R4 配置编排

R4 分两段：先由 WorkBot 生成 YAML 产物，人工填写后上传；再由 WorkBot 用 YAML 生成脚本、做现网同名资源预检，并询问是否真实下发。

### 脚本模式

| 场景 | 固定交互 | 预期结果 |
| --- | --- | --- |
| VS + 节点池 + 前置策略 + HTTP 优化 | `在 AD1 上帮我创建虚拟服务，引用节点池、前置策略和 http 优化策略。` -> 上传填写后的 YAML -> `我写完了 YAML。` -> `直接给出脚本。` | 生成 `adops-bundle.yml`、`apply.py`、`rollback_apply.py`，镜像到 WorkBot 产出物目录，做同名资源 GET 预检，不下发。 |
| VS + 节点池 + 节点 | `在 AD1 上帮我创建虚拟服务，创建节点池并添加节点。` -> 上传 YAML -> `我写完了 YAML。` -> `直接给出脚本。` | 同上。 |
| VS + 节点池 + HTTP 优化 | `在 AD1 上帮我创建一个 HTTP 虚拟服务，引用节点池和 http 优化策略。` -> 上传 YAML -> `我写完了 YAML。` -> `不需要下发。` | 同上。 |
| VS + 节点池 + 前置策略 | `在 AD1 上帮我创建虚拟服务，引用节点池和前置策略。` -> 上传 YAML -> `我写完了 YAML。` -> `先不下发。` | 同上。 |

### 真实下发模式

| 固定交互 | 预期结果 |
| --- | --- |
| `在 AD1 上帮我创建虚拟服务，引用节点池、前置策略和 http 优化策略。` -> 上传填写后的 YAML -> `我写完了 YAML。` -> `真实下发。` -> 人工确认后回复 `是。` | 下发前做 GET 预检；真实调用 `apply-slb-plan`；外部验证资源存在；询问是否回滚；回复后调用 `rollback-and-verify`；外部验证资源不存在；最终给出 YAML、正向脚本和回滚脚本。 |

R4 输出模板固定为 `配置结论 / 产出物 / 下一步`。`产出物` 必须列出 `adops-bundle.yml`、`apply.py`、`rollback_apply.py` 三个真实文件，不能只用文字说已经生成。不要输出 `操作计划`、`计划摘要`、`执行摘要`、`安全确认`，也不要列内部 JSON 文件。若同名资源已存在，WorkBot 应复用现有资源并说明复用对象；若预检无法确认现网状态，必须停止，不能下发。
