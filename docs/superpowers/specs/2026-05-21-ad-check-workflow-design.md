# AD 巡检分析 — 工作流改进设计

**日期**: 2026-05-21
**版本**: 1.0
**方案**: A — 纯 SKILL.md 重写

## 背景

当前 ad-check-analysis skill 存在三个问题：

1. **单设备巡检未提示用户确认**：LLM 直接执行，没有先让用户确认设备、场景、force 等信息
2. **未询问巡检场景**：虽然 SKILL.md 写了"未指定场景时展示列表让用户选"，但 LLM 经常跳过，直接默认标准巡检
3. **单设备/多设备逻辑混在一起**：两者的场景选择、force 处理逻辑不同，但当前文档没有清晰分开

## 设计目标

- 零脚本改动，仅修改 SKILL.md
- 用强制语气 + 决策表替换描述性规则
- 单设备和多设备流程完全独立，LLM 按分支执行
- 关键决策点（场景选择、force 确认）LLM 必须与用户交互，不得自行决定

## 设备判断

| 用户输入特征 | 判定 | 执行流程 |
|-------------|------|---------|
| 提到单个 IP / 单个设备名（如 "AD1"、"192.168.8.30"） | **单设备** | → 流程 A |
| 提到多个 IP / 多个设备名 / "所有" / "全部" / "批量" / "都" | **多设备** | → 流程 B |
| 未提及任何设备 | **单设备** | → 流程 A，需额外询问设备 |

## 流程 A：单设备巡检

### A1. 确定设备

- 用户指定了设备（IP 或设备名如 "AD1"）→ 直接使用，从 devices.json 查完整 URL
- 用户未指定设备 → **询问用户**要巡检哪台设备

### A2. 确定场景

- 用户消息中包含场景关键词（"标准"、"安全"、"全量"）→ 直接使用用户指定的场景
- 用户未指定场景 → **必须告知用户**"将使用标准巡检"，并给用户确认/修改/取消的机会
  - 确认 → 进入 A3
  - 修改 → 展示可用场景列表让用户选择，然后进入 A3
  - 取消 → 终止流程

### A3. 检查历史记录

- 调用 `check.py history --host ...` 查询历史记录
- `len(items) < 5` → 直接执行 A4（不带 `--force`）
- `len(items) == 5` → **询问用户**："巡检记录已达 5 条上限，强制巡检会删除最早一条记录。是否继续？"
  - 用户同意 → 带 `--force` 执行 A4
  - 用户拒绝 → 终止流程，提示用户可手动清理历史记录

### A4. 启动巡检

```bash
python scripts/check.py run --host https://IP --password xxx --scene "场景名" [--force]
```

### A5. 轮询进度

每 10s 调用 `check.py progress --host ...`，直到 state 变为 FINISHED。

### A6. 下载分析

```bash
python scripts/check.py wait --host https://IP --work-dir <A4返回的work_dir>
```

### A7. 展示报告

脚本输出的 Markdown 全文展示在对话中，不截断、不折叠。

## 流程 B：多设备巡检

### B1. 确定设备列表

- 用户指定了设备（IP/设备名列表、"所有"、"全部"等）→ 从 devices.json 解析
- 用户未指定任何设备 → **自动从 devices.json 读取所有已知设备**
- 如果只有 1 台设备 → 降级为流程 A（单设备）

### B2. 确定场景

- 用户指定了场景 → 直接使用
- 用户未指定 → **默认标准巡检，直接执行**（不需要确认）
- 所有设备**统一使用同一种场景**，不支持混用

### B3. 启动巡检（不查历史，直接带 --force）

多设备不逐台查历史记录。直接带 `--force` 启动：

```bash
python scripts/check.py run --hosts "https://IP1,https://IP2" --password xxx --scene "场景名" --force
```

### B4. 轮询进度

每 10s 调用 `check.py progress --hosts "..." --password xxx` 并行查询所有设备。

### B5. 下载分析

每台设备分别调用 `check.py wait --host ... --work-dir ...`。

### B6. 展示报告

多设备报告含汇总表 + 每设备详细报告，全文展示。

### 关键改动点

1. **工作流决策树放在 frontmatter 之后第一位**：LLM 加载 skill 时第一眼看到，无法错过
2. **每步标注"必须"/"询问用户"/"自动"**：LLM 清晰知道何时必须与用户交互
3. **原有"执行步骤"章节删除**：内容合并到流程 A/B 中，避免重复和不一致
4. **"巡检场景选择规则"和"巡检记录限制"独立章节删除**：逻辑内化到流程 A/B 中
5. **description 更新**：补充"安全巡检"触发词

## 边界情况

| 情况 | 处理 |
|------|------|
| 多设备只有 1 台 | 降级为流程 A（单设备），走完整的场景确认和 history 检查 |
| devices.json 不存在或为空 | 报错提示用户配置设备清单 |
| 用户指定的场景在设备上不存在 | 调用 scenes 获取实际列表，告知用户并让用户重新选择 |
| 单设备 history 报错 | 原样展示错误给用户，不自行补救 |
| 多设备部分连接失败 | 脚本返回 exit code 7，汇总报告中标注连接失败/认证失败的设备 |
