# 排查建议优化方案

**日期**: 2026-05-22
**状态**: 待审批

---

## 当前问题

单设备报告的"优化建议"区块存在三个问题：

### 1. key 不匹配

`_SUGGESTION_MAP` 使用旧 v2 的 rule_id（如 `base_cpu_info`、`ssh_or_adapi_authority`），但现在 `check_results` 的 key 是 CHECK_RULES 的 key（如 `CPU_CHECK`、`SSH_API_CHECK`）。大部分匹配失败，走了通用兜底。

### 2. 兜底文本太机器

```markdown
| 高 | SSH与API权限检测 | 检查项 SSH与API权限检测 状态为 fail，建议进一步排查 |
```

"建议进一步排查"对每个异常项都一样，没有提供任何有价值的行动指引。

### 3. 功能价值低

巡检报告已经有 ❌ 异常标记，重复一句"建议进一步排查"没有增量信息。用户需要的是**具体可操作的排查方向**。

---

## 方案

重写 `_SUGGESTION_MAP`：key 改为 CHECK_RULES key，value 为具体可操作的排查建议。一检查项一文案，覆盖率 67/67，删除通用兜底文本。

区块标题从"优化建议"改为"排查建议"。

## 实施

1. 重写 `_SUGGESTION_MAP`：key 为 CHECK_RULES key（共 67 条），value 为上述排查建议
2. 删除 `_SUGGESTION_MAP.get(key, f"检查项 ... 建议进一步排查")` 中的 fallback 兜底文案，找不到 key 时使用 `"检查项 {name} 状态异常，请关注"` 作为最低兜底
3. 区块标题从"优化建议"改为"排查建议"
4. 多设备模板 `render.py` 中的 `_render_suggestions_multi` 标题同步更新
5. 57 条是 `warn` 降级通知 → 全部统一为 `fail`（之前的重构已做完这一点，此处确认一致）

预估工作量：新增 67 行映射字典，修改 2 处标题，删除 1 行 fallback。
